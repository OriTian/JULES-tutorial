# Cleaning up the EC2 instance

The tutorial's t3.micro instance has a small root volume, and a full
setup + build + a few runs can fill it up. `cleanup_ec2.sh` clears out
everything that's safe to regenerate.

```bash
cat > ~/cleanup_ec2.sh << 'EOF'
# ...paste cleanup_ec2.sh here...
EOF
bash ~/cleanup_ec2.sh
```

## What it removes

**Default (soft clean)** — removes run outputs and the build directory,
keeps the installed toolchain:

```text
~/kcl_default/, ~/kcl_usurf/    run directories and their output/     (from get_run.sh, jules.exe)
~/london_stjamespark/, ~/my_first_run/, ~/*_run/   older run directories
~/jules-tutorial-data/          unpacked tutorial data                (from get_run.sh / README Step 24)
/tmp/jules-tutorial-data.tar.gz downloaded archive                    (from get_run.sh / README Step 24)
~/jules_build/                  compiled jules.exe and build tree     (from build_jules.sh, ~1 min to rebuild)
pip / conda package caches
```

**`--deep`** — also removes the toolchain itself, resetting the instance
back to before `setup_ec2.sh` was ever run:

```bash
bash ~/cleanup_ec2.sh --deep
```

```text
~/miniforge3/    conda + netcdf-fortran + Python packages
~/fcm/           the FCM build tool
~/jules_source/  the cloned JULES source
~/install.log    the install log, and the conda/pip caches
```

`install.sh` puts all of it back in a few minutes.

Use `--deep` before handing the instance off to someone else, or if you're
tight enough on disk that the soft clean isn't enough.

## What it never touches

- The 2GB **swapfile** created by `setup_ec2.sh` — it's instance
  infrastructure, not tutorial state, and removing it needs `sudo` either
  way.
- Anything in this repo (`namelists/`, `scripts/`, `data/`) — none of that
  lives on the EC2 instance's disk in the first place; it's fetched fresh
  each time by `get_run.sh` (or the README's Step 24).

Safe to re-run at any time — everything it deletes is regenerated by
`setup_ec2.sh` / `build_jules.sh` / `get_run.sh` / `jules.exe`,
never hand-edited, so there's nothing here to lose.
